# 子Agent大文件生成超时规避

## 问题
mimo-v2.5-pro 模型在子agent中生成大型文件(>2000字/300+行HTML)时，ReadTimeout after 120s+。
三个子agent并行生成大文件时尤其严重（资源竞争）。

## 根因
- 单次输出token量过大（3000+字中文 ≈ 4000+ tokens）
- mimo推理模型生成长文本比通用模型慢
- 子agent有独立timeout（600s），但LLM API本身先超时

## 规避策略

### 策略1: 直接写入（推荐）
不用子代理，主agent直接用write_file写入。
分多次write_file，每次控制在800行以内。

### 策略2: 拆分子任务
将"生成3000字文档"拆成"生成5个600字章节"，
每个子agent只负责一小节。

### 策略3: 模板+内容分离
先写HTML骨架(template)，再用patch填入内容。
避免一次性生成完整大文件。

### 策略4: 对于商业计划书等大型HTML
先用子agent读取参考文件获取风格规范，
然后主agent直接分段写入（每段200-300行）。

## 适用场景
- 商业计划书HTML (>500行)
- 设计文档 (>3000字)
- 大型组件代码 (>500行)
- 任何预计输出 >20KB 的任务
