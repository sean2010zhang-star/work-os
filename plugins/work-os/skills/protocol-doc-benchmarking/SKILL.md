# Protocol/Skill 文档基准评测与迭代

## When to Use

- 用户要求"比较/评测/打分多个协议或 skill 版本"、"学某仓库再和我的体系比"、"修复问题提升得分"类任务。
- 升级开发协议/长程战役类文档需要客观证据而非自夸时；任何"流程文档到底防不防得住坑"的验证需求。

评测对象是"流程协议类文档"（开发协议、skill、SOP）：没有可执行代码可测，能测的是**按文档行事的 agent 会不会掉进已知坑**。

## 核心方法（顺序即流程）

1. **先建判据，后出题，再派 Runner**。评分要素在 Runner 看到题之前写死落盘（rubric.md），与任何被测文档无关。
2. **题源=真实事故，不是被测文档**。从用户的永久记忆库/决策记录/事故复盘里收集匿名化事故原型，每起事故出一道"迷宫题"。
3. **多版本对照同套题同判据**，输出逐题得分表 + 诚实声明残余分去哪了。
4. **修复后必须用同一套题复跑**，全部要素有明文命中才许声明升级完成；未复测的修复项要标注"未复测"，不得计入得分。得分汇报用全版本曲线表（每轮版本 × 每题得分），并逐题写明残余分去向分类——"有判据无脚本""有脚本未接入流程""纯文字叮嘱"三类是标准残余口径。

## 出题偏置陷阱（本方法存在的理由）

- **禁止从被测文档"对称取并集"倒推题目**：题目若按 A 文档的环节+ B 文档的环节拼出来，融合版必然满分（实测：对称题给融合版 97.5/100，同一融合版换真实事故题只有 66）。同理，"提升清单"若也是从文档对照倒推的，必然漏掉文档外事故型。
- 每道题预先声明 2-3 个中立判据要素（"要素: a)…b)…c)…"），Runner 无权改动判据；"本协议未覆盖"=0 分不加罚，**编造文档中不存在的条款倒扣**。
- 题目优先考**事前预防**多于事后补救；纯文字叮嘱与脚本/命令支撑必须区分给分（机械化加分项单列）。

## Runner 纪律

- 每轮评测派**全新 Runner**（不知晓上轮答案），防锚定偏差；输出被截断需要续答时，续接原子会话补答（保上下文又不重答）。
- Runner prompt 必含：只依据指定文档、禁止借用其他版本或文档外常识补答、每题标注[依据]原文短语+所在节。
- **防截断**：给 output_schema 每题加 maxLength（如 400），prompt 写"宁短勿缺、全部 N 题必须输出完整"——长答案多题场景无此限制会中途截断。
- **被测文档含脚本/工具时，Runner 必须实读脚本源码**核对"文档声称 vs 代码实现"，不符点名。高频真实缺陷：docstring/表格里声称某检测已实现、函数体里根本没有（只留了注释）；或声称扫 mtime 实际只读 ts 字段（ts 可被未来值绕过）。声称与实现不符 = 该要素不给机械化分。

## 迭代循环

```
真实事故题集 → 各版本打分 → 残余缺口清单（按"有判据无脚本"/"有脚本但没接入流程"/"纯文字叮嘱"分类）
→ 修复：能静态判定→写成确定性脚本并【当场实测】（构造正反两个用例：事故态必须 BLOCK、健康态必须 PASS）
→ 文档把脚本名/参数/接入点写进对应 Gate 步骤，而不只写进武器库表
→ 同套题换新 Runner 复跑 → 循环直到无"未覆盖"空题
```

- 每轮修复后先跑脚本正反用例再谈得分；只改文档不实测 = 上轮教训的重演。
- **修复声称本身要被独立复验**：修复轮的 commit message / 武器库表里写"N/N 实测通过"不构成证据——收紧白名单式修复自己会引入新洞（条件动词漏收、docstring 声称的参数 argparse 里不存在、相对 import 静默豁免）。复跑轮给 Runner 的 context 里显式列出"上轮修复点清单"，并在 output_schema 加必填 `fix_verification` 字段，要求逐条实读源码核对后才计分。
- 正则类静态检测修好后必须**重跑 bad 用例确认从漏抓变命中**，别假设新正则就工作：跨行/两语句语义（如"变量=存储读取…后续与字面量比较"）单条正则会漏（字符类跨不了行），写成两趟行级判据（第一趟收集变量名，第二趟比对），且 good 用例必须零误报才算过。
- **文字禁令的升级终点是白名单拦截闸**：一条禁令哪怕写全了"适用对象=所有被派 agent"仍是文字——若禁令内容是"禁止某类命令的写操作"，把它做成包装闸脚本（只读动词白名单透传+写动词非零退出拒绝+deny 事件落审计文件），再让协议条款把"派单契约"指向该闸作为执行载体；用"预期 ALLOW/DENIED 动词矩阵"逐个实测全对才算数。
- 矩阵测试整批输出异常（got=??/RC=128/找不到路径）时先查测试夹具本身存不存在（scratch 目录会被清理）——闸脚本先放行、下游命令因仓库缺失而败，是 harness 漏洞不是闸 bug，别急着改脚本。
- 修无可修时诚实登记"已知机检边界"清单（哪些仍是流程条款无脚本），不许用文字虚报机械化；闸类脚本若只靠派单模板注入（非 OS 沙箱强制），把这一层也登记进边界，别声称"已剥夺写权限"。
- 真实战役/真实项目的实跑是最终 judge——文档级满分不代表实战成立，把"下次实跑就是 formal run"写进结论。

## 环境陷阱

- 批量 shell 命令引用含空格路径（外接盘、中文目录）必须对**每个**路径逐个加引号；未加引号的变量展开会把路径按空格劈开。文件遍历+编译检查走 Python 侧可完全绕开。
- write_file 整文件覆盖易被"声称 vs 实现"打脸：优先 patch 定向改；改完必跑 py_compile+正反用例。
- 多版本对比存档：原始快照（被测文档+其安装目录）先整体 copytree 到固定存档目录再动手改，保证评测可复现。
