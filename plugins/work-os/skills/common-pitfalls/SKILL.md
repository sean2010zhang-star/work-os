# 跨项目通用陷阱库 V2.0

## 设计原则

V1.0问题: 教训锁在各项目的skill里，新项目重复踩坑。
V2.0方案: 提取跨项目共性教训，按领域分类，新项目自动加载。

---

## FastAPI 陷阱

### P0: 双参数Body Bug
```python
# ❌ FastAPI无法解析两个同类型body参数 → 422必现
async def create_plan(data: Schema, req: Schema, ...):
# ✅ 只保留一个参数名
async def create_plan(data: Schema, ...):
```
检测: `grep -rn 'async def.*data:.*Req.*req:.*Req'`

### P0: Router Prefix冲突
两个router注册到同一prefix，重复路由永远不可达。
检测: `grep -rn 'include_router' main.py` + 检查prefix

### P0: 前后端API路径不匹配
前端api.ts定义的路径与后端router不一致 → 上线404。
检测: 提取两端路径列表做diff

### P0: Pydantic .get()崩溃
`data: dict`改为`data: PydanticModel`后，`data.get("key")`报AttributeError。
改schema后立即grep `.get(` 并替换为 `data.xxx`

### P0: 路由参数名混乱
同一router中部分用`data`部分用`req`，甚至有两个同类型参数。
统一用`data`作为参数名。

### P1: Response格式不统一
有的用`{code,message,data}`，有的直接return dict。
策略: 新端点用raise HTTPException，旧端点不改。

## 部署陷阱

### P0: .env被tar覆盖
本地.env(含PostgreSQL URL)打包上传覆盖云端.env(含SQLite URL)。
铁律: `tar --exclude='.env'`

### P0: bcrypt 5.x不兼容passlib
bcrypt 5.x移除__about__模块 → register返回500。
修复: `pip install 'bcrypt==4.0.1'`

### P0: 端口冲突
启动前必须 `lsof -i :PORT` 检查。
推荐: 后端8001/8002, 前端3009(避免常用端口)

### P1: 腾讯云安全组未开放端口
服务正常运行但外部无法访问 → curl返回000。
修复: 控制台→防火墙→添加规则

### P1: tar上传覆盖.env
每次打包前检查是否排除了.env。

## 前端陷阱

### P0: 骨架交付冒充完成
前端用setTimeout/MOCK_常量/硬编码假数据 → 功能未完成。
检测: `grep -rn 'setTimeout|MOCK_|// Mock' --include='*.tsx'`

### P0: 参考前端风格未对齐
用户给出参考代码但agent自己重写 → 风格不一致。
铁律: 直接使用参考代码，只改品牌名和功能映射。

### P1: 品牌名残留
sed替换90%，但JSX拆分元素(`Career<span>Forge</span>`)需手动patch。
验证: `grep -rn "OldName" src/` 确认零残留

### P1: 页面顺序跳跃
页面Tab必须按用户故事流排列，不是按功能模块。
用户原话: "页面顺序要按照故事流进行，不要跳跃"

### P0: IntersectionObserver不触发已在视口的元素
用IntersectionObserver做滚动入场动画时，页面加载时已在视口内的元素可能不触发回调 → 元素永久不可见（如果CSS设了opacity:0）。
**铁律**: 元素默认可见，只在滚动进入时添加动画效果。必须有安全兜底（timeout强制可见）。
**详见**: `resume-portfolio-builder` skill的`references/tailwind-animation-injection.md`

### P1: localStorage陷阱
前端用localStorage持久化+hardcoded默认值，看起来有数据但从未调用API。
正确: API优先 + localStorage作为离线fallback

### P0: 重复 import 同名标识符 = 全模块图死亡
同一模块内两处 import 导出同名符号（`import { X } from a` + `import { X } from b`）→ `Identifier 'X' has already been declared` → 该模块及全部依赖页静默空白，无可见报错。
铁律: 浏览器侧交付前必须跑动态探针 `import('/assets/xxx.js').then(()=>'OK').catch(e=>e.message)`——node --check 与 HTML 语法检查都抓不到模块图运行期错误；页面整片空白时第一步跑此探针区分「模块挂死」vs「闸门拦截/数据未出」。

### P1: 本地持久化闸门拦 E2E 的排查顺序
带年龄/资格/凭证闸门的本地应用在浏览器 E2E 中反复出现 claims=0/按钮缺失假象。排查序：①先探测闸门元素是否存在（如 gate 按钮），在则点确认再继续——别急着怀疑刚改的代码；②localStorage 键会在任意轮被清/失效，且 about:blank 上下文读 localStorage 抛 SecurityError——先 goto 到 origin 内任一页面再注入键，注入后重新导航才生效；③凭证/档位键缺失会回落 free 档触发「升级解锁」拦截，症状与代码 bug 相同——结果区文案含「该盘属于 X 档」即凭证拦实锤，不要先改码。修复动作=用项目的签发 CLI 按**被测功能要求的档位**重签（高级功能盘要对应 tier，取编码字段写入凭证键），并把「闸门键+档位凭证注入→再导航被测页」固定为每轮 E2E 开局序——前轮为测降级路径 removeItem 清的键会波及后续所有页的 E2E。

## 内容/课程板块陷阱（用户报「板块根本没法用/什么实际内容都没有」）

### P0: 内容断链按三层彻查再定修复分层，禁止只查一层就下结论
「内容板块空」的三个独立断点，逐层实测取证：①**数据断链声明**——内容索引文件的 `_doc` 自称「正文在 X.md」，但 grep 消费端代码对 X 的引用 = 0（声明了正文来源、代码从未加载，只消费元数据提纲）；②**字数实测**——浏览器点开详情页取 innerText 字数，与「提纲级」（summary+要点合计千字级）对比定虚胖程度；③**数据在场但渲染为零**——索引里有 quiz/body 类字段而 UI 代码 grep 该字段名 = 0 命中（内容做了、管道没接）。修复拆两步各自入库：先**结构层**（正文 Markdown 渲染位 + 交互管道 + 无正文时诚实占位「编写中」，不假装完成——占位态本身要 E2E 烟测）；后**内容层**注入上线。前端极简 Markdown 渲染器纪律：先 escapeHtml 再放标签（防注入），只支持子集（###/列表/表格/**粗**/行内码/引用），禁图片与代码围栏；本地 JSON fetch 开发期加 `?cb='+Date.now()` 防缓存吃到旧数据。判分交互细节：答错的解析文案禁复用「答对了」模板，按对错分支取文案。

### P0: 写手子代理产大量领域文本 = 预生成锚数据封数值编造
子代理写含专业数值（干支/时刻/查表值/流程中间量）的讲义或报告时，必先在主会话用项目引擎**实算**出锚数据全集（探针脚本跑真实输出，含边界盘），写手铁律=「数值只准引用锚、锚里没有就改成不依赖数值的表述，禁止自算编造」；写作规范（铁律+口径+合规红线+锚数据+逐讲侧重）落盘为仓库文档，写手第一步必读、复审可对照；多写手按讲/章分片并行、各写各的 JSON 分片文件，主会话回收后逐项校验整合（锚值比对+红线词表闸+字数下限）再注入数据链。交付物里每单元附自测题时，解析文案同步补齐（常见断点=题目在场、explain 缺席）。

## Python陷阱

### P0: null字节write_file
文件写入工具偶尔引入\x00 → SyntaxError。
每次批量write_file后py_compile验证 + 清理脚本。

### P0: read_file行号前缀
read_file返回`     N|`前缀（如`320|</html>`），误写入文件 → Python报IndentationError，HTML文件结构损坏（浏览器无法渲染）。
**铁律**: 用`terminal('cat path')`获取原始内容用于跨文件写入，或写回前strip行号前缀。
**检测**: `grep -n '^[0-9]*|' output_file` — 有匹配则中招。

### P1: f-string中JSON花括号
f-string嵌入JSON时`{{`和`}}`是转义花括号，嵌套花括号→SyntaxError。
JSON示例在f-string外构建为变量。

### P0: 文档锚点替换=静默假成功，写入与申报之间必须 grep 实据
python `str.replace(old,new)` 在 `old` 不存在时不报错不改动 →「已写入文档」的动作空转；更毒的是后续写入以「上一轮宣称写入过的标题」为锚，错误跨会话链式传播，多个 commit 全部虚报"docs 已记"。铁律：①replace 前 `grep -c` 验证锚点行真实存在；②同一段脚本内写入后立即重读文件 `assert new_marker in content`，或在独立步骤 `grep -c` 新内容标记——申报「docs 已记」的凭证是命中计数，不是脚本无报错；③stdin-heredoc 喂 python 遇非 ASCII 源码报 Non-UTF-8 时整段未执行而 `&&` 链照跑，无报错≠完成；④文档更新优先追加到实测存在的节尾（`cat >>`/在真锚后插），少用整句锚替换。

### P0: shell heredoc 拼接 fallback 链写文件=内容损坏且 exit_code 仍 0
`cat >> f <<'EOF' … EOF || mkdir … && cat > f <<'EOF' … EOF` 这类多 heredoc 兜底链，会把前段 EOF 与后段之间的命令文本泄进目标文件（写成命令行片段，文件异常小）。写/重写文件一律走 write_file/patch 工具；发现文件大小异常先 read_file 全量确认再覆盖，别信链上各步的 exit_code。

### P1: Python版本不一致
macOS homebrew Python(3.11) vs 系统Python(3.9)。
后台进程必须用绝对路径。

## 多引擎一致性 / 对拍陷阱

### P0: 用户报告「两个引擎/两个页面结果不一致」——先 N 盘自动对拍分栏归类，再动代码
直接读代码猜根因容易错归因。固定流程：①写比对探针，同参数跑数百至数千盘，按字段/柱统计差异分布（哪几列差、差多少）；②分解差异为两类——「一条链路漏了处理步骤/参数没传」（真 bug，修=共用另一条的同一计算层函数）与「两体系口径边界不同」（如节气边界⇄农历月边界，传统输出本就不同，非 bug）；③bug 修复 + 口径差如实注记上屏（写明两体系边界规则与已对齐/未对齐范围），绝不强行归一——篡改权威库本体去迁就另一方=制造新错；④回归锁必须钉边界盘：校正跨时辰/跨午夜/跨节气盘 + 双口径并存盘（两个值都断言如实异），敏感时刻（如某节气 22:48）要传 minute 钉死，缺省 0 分会漂到边界另一侧让断言反着红；⑤终验=产品界面同输入两链路对拍一致（浏览器 E2E），不是仅引擎直调探针一致。衍生铁律：(a) 校正/换算链必须**整面喂**——下游函数拿「校正后日期+校正后时分」全套，禁混用原钟面日期+校后时刻（校正值跨午夜/跨节气时混合口径必错一天，单城探针难见，边界盘对拍才现形）；(b) 新口径优先写成**独立自算函数**对拍权威库（非转抄库返回值）——既获可审计复算能力，又会顺带抓出共用依赖层的真 bug（差异集中在特定窗口——如归属翻转全落在某节气附近——是依赖层边界逻辑错的强信号，先修根再接线）；(c) 双口径并陈时展示标签按在场字段动态取名（旧数据只有单值时标签不得谎称某一口径），并陈两值都渲染+分歧才加标记。

### P0: 对拍分歧先找独立第三方源裁判；裁不动就外锁不修，两向都不许假
两主流库一致而自家不同=自家规则错的高概率信号（历法/标准算法尤其：naive 民俗表述常缺标准的窗口判据，如置闰「第一个无中气月即闰」漏了「两冬至间需 12 个完整月才置闰」且错禁闰十一/闰十二月——须查标准文本与权威改正史，不得凭通俗口径实现）。但若两库一致却与权威天文源（历算站/天文台/官方历书）冲突，则**库表自身是错方**（时区换算类），自家算法可能反而对——三源互斥无法裁定：不改，入外锁并写清影响面（哪些年代/窗口边界可能差一）与未来升级权威数据源的触发条件。对拍「宁缺毋假」覆盖两个方向：既别假称自家对，也别假称已可裁定。

### P1: 回归锁钉规则导出值，禁钉亚日精度争议带的日号细节
断言若把朔/节气交节时刻所在边界带内的日号（同一天算 29 还是 30）钉死，会因各家库的表历精度互斥而反噬（首跑红不是逻辑错，是锁过拟合）。写锁前先判定该值属「规则唯一导出」（闰否/月号/年界/干支序——可钉）还是「依赖亚日时刻的归属」（边界带日号——只放宽为区间/结构断言并注释原因，如 `>=29`），边界带值永不入钉值断言。

### P1: 展示/锚定用的「今日日期」fallback 是时区陷阱
`new Date().toISOString().slice(0,10)` 是 UTC 日——东八区凌晨 0–8 时与本地日差一天，用户界面「截至」锚会错且无从核对。凡给用户展示或作为计算锚的本地日期串，必须 getFullYear/getMonth/getDate 手拼本地时区值；调用方不传参时提取层要回填实际使用的值（界面永不为空白），测试的格式/非空断言全天有效，等值断言仅在分歧窗口红——不能只靠后者。

### P1: 归因申报的影响面按探针覆盖面如实限定
对拍探针固定单城/单参跑出的差异计数（如「时柱差258、日柱0」）只是该覆盖面下的下界——独立复审扩多城/随机参后波及面通常更大（同 bug 变 449+日柱也差38）。申报时写明覆盖面（「lon=120 单城口径」），或首轮就随机化经度/开关多维采样；「0 差异」结论必附参数网格，否则复审会当甩锅证据打回。口径类结论（两体系边界差）要有第三方底本/多源佐证钉死（库源码常量、边界日实测、外部文献），单靠自家对拍数字不足采信。

### P1: 同一出生在不同页面必须共用参数面与选项表
同一业务字段（出生地经度、分钟、开关）各表单页有独立副本/不同默认值 → 两页面同输入结果必漂。城市表等选项沉为共享常量（单一真相源）导出，各表单 import；修计算链时同步审全部入口页调用面（参数是否都传了）——「引擎正确」救不了「入口漏参」。

## 测试断言陷阱

### P0: 口诀/名单类知识必须探针从权威源提取后再写断言，禁凭记忆默写
凭记忆默写领域名单（查表口诀、神煞表、库内常量表）写进代码或测试=事故源，多次实测每次都被底本核对或对拍探针抓出。「带出处标注」不构成证据——自写的 basis 文案同样会错并骗过自审。铁律：先用多盘探针从库/权威文本提取实际值全集，再写断言；库实际输出（如某字段实出 10 位而非文献说的 12 位）=断言准绳，按库实际申报，不迁就想象、也不掩饰为降级。

### P0: 命中/未命中式断言封不住表值篡改——必须锁表值字面
篡改基准表某值后全量测试照绿=断言面覆盖缺口（根因：断言盘集不含被篡改值）。封堵模式：查表每一行都有盘使其 hit=true 且展示/basis 串含该字面值；环排类名单加「全部值 ∈ 名单全集 且 N 位互异」内容断言。注意 typeof/非空 式检查是弱锁（笔误键回退的空串同样是 string），升级值内容断言。复审验收标准=重跑篡改探针令对应断言必红。

### P0: 回归锁必须断「被修行为的本体输出」，禁只断元数据字段——篡改复现是锁的验收步骤
修行为时若测试只断 facts/payload 的元数据（如 timeIndex、clock 串、asOf 日期），把实际输出路径退回旧行为后测试照样全绿=修复零防护（症状：元数据在、产物错）。铁律：锁必须钉最终产物本体（渲染盘面/接口响应/计算结果串），断「用户看到的那个值」；每条新锁入库前在探针树做一次篡改复现——注入行为回退→对应断言必红，恢复→绿，红不了=锁没锁上，重写断言目标再入库。申报「回归锁 N 项」时同步申报每项封的是行为还是元数据。

### P1: commit message / 汇报里的计数以当次实跑输出为准
凭记忆写测试计数（377 vs 实跑 375）=申报失实，与「骨架冒充完成」同类。commit 前对最近一次实跑的 `# pass` 行复核；发现即 amend 并在 message 内自我订正声明，不留跨会话的错数。声明基线「稳定/全绿」前，疑似时序 flake 的先排除编辑中脏状态（测试文件改到一半被并发跑到），改完后全量套件连跑两轮一致才算基线——单轮红/绿都不足为凭。

### P1: 浏览器 E2E 对表单控件必须填合法枚举值
select 选项为窗口中值（时辰 0/2/4…）或其他枚举时，填任意值（'9'）+change 事件会被回落默认，症状酷似刚改的功能坏。E2E 前先读控件 options 列表取合法值；结果不符预期先读结果区原文核对实际接收到的输入（含 sessionStorage/参数传递键名与编码格式），再怀疑被测代码。

## 接口演进陷阱

### P1: 查表/纯函数扩展签名必须保留旧调用面兼容
给既有函数加第 N 个可选参数携带新信息（如干支全柱信息）时：①先 grep 全部调用点逐一迁移（渲染层/测试/host 注入点），漏迁的旧调用应走「新特性缺席不猜」分支并有断言锁定缺席态（返回项数门控值即证据）；②新参数缺省时绝不从旧参数猜测补全——缺席=功能项不显示，比错误命中安全；③函数内部注释、上屏 basis 文案、调用层注入形状三者与代码同轮改，任何一处滞后都会在复审时构成口径失实。

### P1: 能力口径表述随实现实测降级
词表/规则类闸门的真实能力（如字面子串溯源 vs 语义匹配）用绕过探针实测后再写验收清单与上屏文案：表外词逃逸、否定翻转可过这类探针结论直接决定文案措辞（「词表内逐字面溯源，可审计非穷尽」），禁止按设计意图写「全部/必回/穷尽」。发现夸大时订正表述优先于扩表（扩表另立需求项排期）。

## 第三方 JS 库集成陷阱（vendor 化压缩库）

### P0: 压缩 vendor 库的 node 探针需三防
把前端压缩库（UMD/IIFE）拿去 node 里探 API 结构时：①`globalThis.self = globalThis` 后再 require（部分打包器依赖 self 判环境，否则模块工厂返回 undefined，症状酷似库坏了）；②库内嵌 throw 字符串跑裸 node 会刷屏整个压缩源码——探针一律逐调用 try/catch + 只 print 目标字段（聚焦输出），绝不 dump 整个对象；③探针脚本保留进 scripts/ 当 API 结构审计证据（ages 长度、某属性真实名称、返回对象形状这类结论靠探针钉，不靠文档记忆）。

### P0: 字段扩展「只增不改名」的铁律执行面
给无 schema 的 facts/payload 加字段时：旧字段名一律保留不改（旧存档/下游消费靠名字）；键名写错后的「改名修正」名义上违反此律——必须 grep 全仓证明零旧键消费者 + 旧键恒为空/无效，并在 commit/发布说明里显式申报一句；渲染/消费层用「新字段在场才启用新行为」（`f.newField ? rich : legacy`）门控，旧数据静默走旧路径，不渲染假新密度。

### P1: 库语义字段靠实测不靠文档/命名推断
同名属性在不同库语义可异（如运限对象里 range 不在自身而在被落宫上；查表函数参数是宫序索引非地支）：接入前写最小探针盘验证每个要展示的字段实际出值，注释里记录探针结论；库对边界输入会抛（非法日期），提取层 catch→null 缺席不猜，渲染层据 null 静默跳过。

## Agent Team陷阱

### P1: 模型不可用(403)
子代理的子Agent可能因模型权限失败。
主Agent必须有fallback能力。

### P1: 并行Agent修改同一文件
两个子Agent都修改同一文件 → 后写的覆盖先写的。
明确划分文件边界，或串行处理共享文件。

### P0: 未提交状态下派审计 = 工作被抹事故
审计子代理为还原判定区间会跑 git restore/checkout/备份恢复，直接抹掉主会话未提交改动；主会话审计期间继续编辑又会让判定对象漂移。铁律：每完成一期先 commit+tag 再派审；派审 context 写明「判定区间 = commit A..B」而非 HEAD；主会话冻结仓库编辑至交卷（期间只做只读探针/外部知识库/文档笔记）。已开工未提交时派审=双重事故，宁可等 commit。

### P1: 审计子代理中断≠审废——探针落盘可回收，派审时强制脚本化
子代理在长审中途被中断（模型响应等待/超时）时 verdict 丢失，但其写进探针目录的独立可跑脚本与部分输出仍在。回收动作：读 live_transcript 尾部确认验证进度与已出结论 → 主会话复跑那些探针脚本收数字 → 仅对未覆盖面补派/自补。预防性纪律：派审 context 必须要求「每个验证项写成探针目录内独立可复跑的脚本，结论打印 stdout」——探针即审计的持久化产出，中断成本降为复跑；回收后自己复现关键数字再采信，部分产出不等于完整 verdict，缺口项如实列出。

### P2: Agent过于乐观
"Agent对自己的工作是病理性的乐观者"。
用独立Evaluator替代self-critique。

## Git 历史陷阱

### P0: reset --soft 的目标必须用 git log 回读到的 hash 锚定，禁凭记忆数 HEAD~N
amend 重切历史时 `reset --soft HEAD~N` 的 N 数错会把无关的前一提交一起折叠进新提交（message 只描述后一件事、实际含全部改动），原 tag 变孤儿——工作树正确但历史误导回滚。铁律：操作前 `git log --oneline` 记下目标 commit 的 hash，直接对 hash 动手；折叠完成后 `git show --name-only` 核对文件集与 message 相符；重整/清理命令被审批网关拦下（超时未批）即保持现状，把回滚路径（孤儿 tag 名+commit hash）如实记入项目谱系与 commit message，不重试、不换命令绕行。
