## L1 理论层: 控制论五大原理

> 完整保留V1.0内容，无变更
> 详见: cybernetics-engineering-control skill (V1.0 backup)

### 原理1: 反馈闭环 (Feedback Loop)
输入→处理→输出→反馈(测量/比较)→校正→新输入
- 无验证的交付 = 开环系统 = 不可控

### 原理2: 分层递阶控制 (Hierarchical Control)
决策层(战略) → 协调层(战术) → 执行层(操作) → 反馈层(监控)
- 三省六部制 = 分层递阶的中国古典实现

### 原理3: 稳定性优先 (Stability First)
稳定性 > 精确性 > 最优性
- 先保证不崩，再追求最优

### 原理4: 信息质量决定控制质量 (Information Quality)
信噪比(SNR) → 控制精度 | 完备性 → 控制范围 | 时效性 → 控制速度
- 模糊需求 = 高信息熵 = 必须先降噪再执行

### 原理5: 适应与自组织 (Adaptation & Self-Organization)
环境变化 → 状态感知 → 参数自整定 → 结构调整 → 新平衡
- Skill库 = AI的自组织知识结构

## L2 规划层: 模式选择 + 方案确认 + 风险识别

> 合并V1.0: L2铁律 + L3方案确认 + L7高风险模式 + work-mode-selector

### 2.1 任务模式判定 (M1-M18)

任务到达时必须判定模式，不可跳过。

**选择决策树(简化版):**
```
任务到达
  ├─ 查询/≤2文件？ ────→ M1/M2 (直接执行)
  ├─ 独立子任务？ ──────→ M3 (并行)
  ├─ 验证/调研？ ──────→ M5/M6 (实验/研究)
  ├─ 中型功能？ ───────→ M7 (方案模式，默认)
  ├─ 需要测试？ ───────→ M8 (TDD)
  ├─ 5+步骤？ ─────────→ M9 (Kanban)
  ├─ 可拆子任务？ ─────→ M10 (子agent)
  ├─ 大型工程？ ───────→ M11/M12 (三省六部)
  ├─ 创业/商业化？ ────→ M15/M16 (OPC/创业)
  ├─ 持续优化？ ───────→ M18 (自主循环)
  └─ 其他 ─────────────→ M7 (方案模式)
```

### 2.2 方案确认 (L1-L4)

| 级别 | 适用场景 | 执行方式 |
|------|----------|----------|
| L1 | 单文件/查询 | 直接执行 |
| L2 | 多独立子任务 | delegate_task并行 |
| L3 | 多步骤需确认 | plan→confirm→execute |
| L4 | 多模块/系统级 | 三省六部+分阶段 |

**三步流程:**
1. **Gap Analysis** — 读真实schema, 列有/缺矩阵, 按P0-P3分类
2. **写PLAN.md + 等确认** — "请确认此方案是否可以执行？"
3. **执行** — 按PLAN.md逐步执行

### 2.3 风险识别

| 反模式 | 诊断 | 处方 |
|--------|------|------|
| 无验证的交付 | 开环控制 | 加反馈环节 |
| 一次改多处 | 扰动过大 | 逐步变更+验证 |
| 需求不清晰就动手 | 信息质量差 | 先降噪再执行 |
| 重复犯同一错误 | 无学习机制 | 更新skill |

## L3 执行层: Sprint三级 + Gate 5门控 + 蜂群

> 合并V1.0: L4 Sprint+Gate
> 详见: sprint-with-tiers skill

### 3.1 Sprint三级制度

| 级别 | 适用场景 | Gate | 审核 | 备份 |
|------|----------|------|------|------|
| 轻量 | ≤3文件, L1-L2任务 | Gate 1+2 | 无Agent Team | Git+session-log |
| 标准 | 4-10文件, L3任务 | Gate 1-4 | Agent Team 3 Agent | 完整4件套 |
| 重型 | 10+文件, L4/架构变更 | Gate 1-5 | 多模型交叉审计 | 完整4件套+全量 |

### 3.2 Gate 5门控体系

| Gate | 名称 | 轻量 | 标准 | 重型 |
|------|------|------|------|------|
| 1 | Pre-flight(文件存在) | ✅ | ✅ | ✅ |
| 2 | Revision(API+语法+构建) | ✅ | ✅ | ✅ |
| 3 | Integration(前后端打通) | - | ✅ | ✅ |
| 4 | 终审(Agent Team) | - | ✅ | ✅ |
| **5** | **用户价值(V2.0新增)** | - | - | ✅ |

### 3.3 交付4件套

| 件套 | 轻量 | 标准 | 重型 |
|------|------|------|------|
| Git commit+tag | ✅ | ✅ | ✅ |
| 文件备份(tar.gz) | - | ✅ | ✅ |
| <vault>更新 | - | ✅ | ✅ |
| session-log会话记录 | 一行摘要 | 完整记录 | 完整记录 |

### 3.4 蜂群限流

| 蜂种 | 工具 | 适用 | 限流 |
|------|------|------|------|
| 工兵蜂 | execute_code | 批量代码 | ≤50次/批 |
| 侦察蜂 | delegate_task | 调研 | ≤3并行,只读 |
| 战斗蜂 | 主Agent | 核心逻辑 | 不可委托 |
| 审计蜂 | delegate_task | 审核 | 3并行,只读 |

### 3.5 Sprint成本追踪(V2.0新增)

```
Sprint N 成本: 开发X + 审计Y(占比Z%) + 备份W = 总计
P0发现: N个 | 每P0成本: 总计/N tokens
```
