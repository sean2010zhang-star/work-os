# 批量文本内容生产线（subagent 写手 + 锚数据防编造 + 程序化校验门）

适用：需要生成大量**含事实/数值/口诀的文本**（课程讲义、手册、百科词条、文档正文）且错误数值=招牌被击穿的场景；也适用用户报「某板块根本没法用/没内容」的彻查。

## 一、「板块没内容」彻查序（先定位断链层，再谈生产）
1. **数据文件自述 vs 消费端实际加载**：读内容 index/JSON 的 `_doc` 声称（如「正文在 xx.md，本文件提供元数据」），再 grep 宿主代码实际 fetch 了什么 URL、消费了哪些字段——「正文在另一文件但 UI 从不加载那个文件」是结构性断链，元数据再全也是空壳。
2. **渲染代码 grep 功能关键词**：数据里有 quiz/body/正文字段 ≠ UI 消费了它；`grep -c "quiz" 渲染.js`=0 即「有数据无接线」死件。
3. **浏览器实测上屏字数**：打开详情页量 `innerText.length`（实测提纲页仅 205 字/讲），用数字定性「虚胖」，不凭文件体积推断。
4. 词典/引用完整性类「缺失」报错先验探针自身口径（`terms[].key` vs 我按 `t.term` 取——口径错=45 个全误报缺失），再报产品缺陷。

## 二、锚数据防编造（写手管线核心）
- 主会话**先用引擎/工具实算出一份「锚数据表」**（干支/时刻/序列值/查表结果——每类示例盘跑一遍真实代码取输出），写进写作规范文档，声明**锚数据=唯一合法数值源**；写手禁止自行推算编造，锚外内容一律改「以引擎为准」表述。数字类幻觉从「审出来」前置为「写不出」。
- 规范文档必含：口径铁律（产品冻结的流派/边界口径逐条列）、合规红线词表（每类禁区的具体禁语+批判语境豁免说明）、结构模板（每篇统一小节骨架）、输出契约（严格 JSON、讲号=键、无代码围栏/图片/链接语法——**先核对渲染器实际支持的语法子集再写禁令**）。
- 按讲/章节分片派 N 个并行写手，各写各的 JSON 到 scratch，文件边界互斥（防并行覆写）。

## 三、主会话程序化校验门（写手自检只是申报）
一次 execute_code 全量跑六类断言：字数下限 / 渲染器不支持语法（围栏、![]、[[、嵌套列表）/ AI 腔词表 / 红线词表 / **锚值在场** / 结构六段齐。然后：
- **红灯先分诊再修**：真缺陷（围栏、字数不足）才动内容；校验器自身过严（四柱串要求空格连写、正则没带「要」字、批判语境里的禁词子串如「不做改运」）判误报定性留痕。**每个校验串先对已知正确语料试跑校准**——未经校准的 checker 会把一批合规内容打回重写，浪费整轮。
- 扩写/修补段落（主会话自己写的）与写手稿**同权送检**——「刚写的」不豁免，实测主会话扩写的口诀推导就带错（见下）。
- 合并注入后 grep 落盘验证 + 浏览器实测渲染上屏字数/表格数，再 commit+tag。
- 文本层质量测试锁覆盖不到——派独立内容审（任务书：锚值全查+口径抽查+红线逐讲+手算链**独立复算**而非对照锚表+对引擎重跑示例盘核文案）。

## 四、结论对≠推导对（值神类内容的第二道锁）
终值对账只锁终点：周期序列的两个错误推导（漏三神、起点词错）可落同一正确终值，终值对账照过。任何文中引用的循环序列（十二神/十二长生/纳音表）必须 grep 代码里的序列数组定义逐字核对，而不是只对「该盘的结果值」。写手默写表值时同理：核定义不只核抽查值。
