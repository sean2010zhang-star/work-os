# Agent Team 审计迭代模式(实测)

## 场景
全量项目开发后，需要独立Agent Team做代码质量/架构/安全三维审计。

## 迭代模式
```
第1轮审计: 3 Agent并行 → 发现14个P0
  ↓ 修复全部P0
第2轮审计: 1 Agent重审 → 发现5个残留P0
  ↓ 修复残留P0
第3轮审计: 1 Agent重审 → P0清零，评分 7.0/7.5/7.5
  ↓ 继续优化
第4轮审计: 1 Agent重审 → 评分 7.5/8.0/7.0
```

## 评分变化
| 维度 | 第1轮 | 第2轮 | 第3轮 | 第4轮 |
|------|-------|-------|-------|-------|
| 代码质量 | 7.2 | 7.5 | 7.0 | 7.5 |
| 架构评估 | 8.2 | 8.0 | 7.5 | 8.0 |
| 安全审计 | 4.4 | 6.2 | 7.0 | 7.5 |
| P0数量 | 14 | 5 | 1 | 0 |

## 关键发现
1. Agent Team比单Agent发现率高3倍
2. 安全审计Agent（GLM-5.1）比代码质量Agent（mimo-v2.5-pro）更严格
3. 从4.4→7.5的安全分提升主要靠：白名单赋值/sanitize全覆盖/流式上传/原子额度/登录限流
4. 7.0→9.5的差距需要深层重构（Redis限流/异步队列/Alembic迁移），超出MVP范围

## P0修复清单（按优先级）
1. 批量赋值漏洞 → 白名单字段赋值
2. AI Prompt注入 → _sanitize正则+多语言覆盖
3. 文件上传OOM → 流式读取+实时大小检查
4. TOCTOU竞态 → SQL UPDATE WHERE原子操作
5. 不安全默认值 → 生产环境启动校验
6. 登录暴力破解 → 内存计数器5次/5分钟
7. JWT异常 → 分层捕获(Expired/Invalid/Generic)
8. UUID校验 → 在DB查询前执行
9. CORS → 显式methods+headers
10. 密码策略 → 8位+手机号正则
11. LLM raw响应不返回客户端
12. imports全部模块顶部化
13. _MOCK_TEMPLATES模板分离
14. _validate_uuid/_apply_score提取消除重复

## 需求-功能对比审查（独立Agent）
- 读取产品设计文档提取所有功能点
- 逐项检查后端API+前端页面+前后端打通
- 标记状态：完全实现/部分实现/未实现/明确推迟
- 输出完成度百分比和缺失功能清单
