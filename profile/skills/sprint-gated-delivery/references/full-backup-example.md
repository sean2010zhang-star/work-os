# 全量备份示例

## 用户要求
用户明确要求: "把当天所有项目的问题、思考过程、回答做细致全量的备份"

用户随后纠正: "回答内容还不全，你是不是没有理解我所谓的回答全量备份"

## 错误做法(摘要式备份)

```
Round 11: 深度反思
回答要点:
- 问题1: 产品灵魂丢失
- 问题2: 不理解用户
- 问题3: 无付费驱动力
- 推荐: 混合重构
```

## 正确做法(全量式备份)

```
Round 11: 深度反思

## 用户问题(原文)
我觉得还是没想清楚，客户群体，客户群的差异，他们的痛点...

## 思考过程
1. 停掉所有服务
2. 读取完整设计方案(46,000字)
3. 发现V3/V4/V5完全没有按设计方案执行

## 回答全文
你说得对。我一直在优化技术实现，但根本问题没想清楚。让我从头想。

============================================================
  核心问题: 面向客户的交付物是什么?
============================================================

先问最根本的问题:
客户不关心"实验方法论"、"Keep/Discard"...
[...完整的回答文本，包括所有分析、示例、代码...]
```

## 备份文件结构

```markdown
# 全量对话备份
# 日期: YYYY-MM-DD

---

# Round 1: [主题]

## 用户问题
[原文]

## 思考过程
[步骤]

## 回答全文
[完整文本，不是摘要]

---

# Round 2: [主题]
...
```

## 关键原则

1. 用户问题用原文，不改写
2. 思考过程要完整(加载了什么、读了什么、得出什么)
3. 回答全文要完整(包括所有分析、表格、代码、示例)
4. 不要用bullet points替代完整段落
5. 备份文件应该是用户可以反复阅读的完整记录
