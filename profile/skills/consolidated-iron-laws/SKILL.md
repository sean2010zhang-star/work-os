# 三级铁律体系 V2.0

## 设计原则

V1.0问题: 60+条"铁律"平铺，agent无法区分优先级。
V2.0方案: 三级分层，5条底线不可违反，10条建议违反需理由，N条实践参考即可。

---

## 第一级: 不可违反(5条) — 违反=交付失败

### 1. 方案确认后才能执行
L3+任务必须先写PLAN.md等用户确认，再执行。
- "帮我处理" = 立即执行(L1-L2)
- "重构某模块" = 必须先确认(L3+)
- 用户说"go"/"继续" = 授权连续执行

### 2. 前后端必须真实打通
禁止以下任何一项冒充"完成":
- 前端用setTimeout/MOCK_常量/硬编码假数据
- 后端API存在但前端从未调用
- 模块有router但返回stub
- AI功能未接真实LLM API

**验证**: grep 'setTimeout|MOCK_|// Mock' + grep 'api\.|API\.' 确认前后端打通

### 3. 备份不可跳过
每个Sprint至少执行Git+session-log。标准/重型Sprint执行完整备份。
- "下次再备份" = 现在就做
- 只做Git不做其他 = 不合格

### 4. Gate验证不可跳过
每个Sprint必须过Gate，即使是轻量Sprint也至少过Gate 1+2。
- 连续交付 ≠ 跳过验证
- 3次FAIL → Escalation，不可静默跳过

### 5. 完成度<80%不许说"完成"
必须对照设计文档逐功能验证:
- ✅完全实现(后端API+前端页面+前后端打通)
- ⚠️部分实现(有代码但mock)
- ❌未实现
- 📅推迟

## 第二级: 强烈建议(10条) — 违反需要明确理由

### 6. 任务到达先判定模式
不可跳过模式选择直接执行。告知用户判定结果。

### 7. M7+必须加载对应skill
skill中有详细流程和陷阱，不加载容易遗漏关键步骤。

### 8. Phase-by-phase自审查
每阶段自检后git commit，用户只确认方案+最终结果。

### 9. 文件创建用execute_code
批量文件创建用execute_code+write_file，不用delegate_task(必超时600s)。

### 10. 核心逻辑主Agent直接实现
算法/架构决策不委托给子agent。

### 11. 审计Agent只读不写
独立上下文，不看执行过程，只产出报告。
并行开发期间审计代理绝对禁止 git checkout/stash/reset/restore（会静默冲掉主会话未提交改动）；需干净树用 git worktree add 独立目录。审计范围必须区间制（从X到Y）且派单前先 commit 当期成果。

### 12. P0修复后必须重审
迭代审计直到P0=0。每次修复可能引入新问题。

### 13. 先验证再改
不是改了再验证。技术选型/架构变更先做spike验证。

### 14. 用户反馈是校准器
技术指标PASS但用户不满意 = 需要重新审视。

### 15. Skill用硬规则语气
铁律/必须/禁止，不用引导式/建议式。

## 第三级: 最佳实践(N条) — 参考但不强制

### 技术类
- JS单行语法错→整个script块死，必须node --check
- cardHtml中</div>必须在条件分支后
- onclick必须显式传this，浏览器JS不可用require()
- 前端wsApi()直接r.json()，数组必须直接返回
- 测试夹具必须用引擎真实输出形状（先实跑dump存fixtures），手造字段=掩盖渲染退化
- 宣称的数字一律动态取自与自引复现命令同一数据源，禁手写常数
- catch分支必须区分fetch失败与代码异常（console.error留痕），吞TypeError=把缺陷伪装成离线
- 分享/导出通道对文本内容做敏感模式遮花(scrubSensitive)，键名扫描防不住用户把敏感数据写进问句
- 仓库内静态服务默认仅绑127.0.0.1+敏感路径硬denylist；审计必查"当前跑着的服务能否curl到私钥"
- 价格/档位/效期声明唯一真相源=CATALOG/manifest数据文件，UI字面量=副本必漂移

### 工程类
- 不盲目学习，不预防性过度工程
- 文档 ≠ 效果
- 端口按需启动不永久运行

### 备份类
- 四层备份(全量时): Git→外存→<vault>→session-log
- 外存rsync排除node_modules/.git/__pycache__

### 设计类
- 前端保持参考代码原风格
- 零容忍gradient/glow/box-shadow
- 页面按故事流排列

### 部署类
- tar打包必须--exclude='.env'
- bcrypt==4.0.1 (5.x不兼容passlib)
- 启动前lsof -i :PORT检查端口

详见: common-pitfalls库 + 各skill的Pitfalls段落

## 铁律审计(月度)

每月检查铁律执行情况:
- 哪些铁律被违反了？→ 违反频率
- 违反是因为agent疏忽还是铁律本身不合理？
- 高频违反的铁律 → 考虑降级或修改

## 质量红线增补（V3.4 战役协议实测回灌）
- 门禁命令禁止 `cmd | tail; echo $?` 取码——管道取到的是尾命令退出码，整役 Gate 会纸糊；一律 subprocess 直取退出码并做一次负向自检（故意红一条，确认被记红）
- 测试/排查常量禁止手抄工具或界面显示值——显示层可能打码/省略号化（U+2026 可能是真实内容）；程序化从代码 import 或 grep 原始文件直取；异常值先怀疑观测层再怀疑被测层
- pin 模型/通道必须过验证三则：直连端点（不经 fallback 链）+ 回读响应体实际模型 ID + 验证与使用同参数；"返回 OK" 是假象，自报"实际模型"字段须网关抽查复核
- 文字禁令必须显式写出适用对象（对哪些 agent 生效），否则形同虚设；agent 一律不碰 git 写操作，禁令升级为技术拦截闸（gitguard）
- 开工前提核验：目标仓库必须已 git 化 + 存在可用备份目标，缺一即 Gate 0 缺口——目录一删全灭
- 状态文件冲突裁决规则预写：机器态(mission.json)为唯一权威，人读态(STATUS.md)反向迁就禁止
- 长战役配外部看门狗：心跳是文件不是口供，主 Agent 自身卡死也要有人报（mtime+ts 双证据）
