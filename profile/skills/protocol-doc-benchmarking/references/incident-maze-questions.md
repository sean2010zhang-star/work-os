# 长程/复杂项目事故迷宫题库（十类原型）

通用化事故原型——出题时把机制描述换成目标项目具体形态，但**保留判据要素结构**（每题 2-3 个事前可验证要素）。适用：评测任何声称管理多期/多人/长周期开发的协议文档。题源必须是真实事故（记忆库/决策记录里检索"事故|教训|冲掉|假故障|回归"类关键词），不得从被测文档倒推。

## C1 并行干扰（只读代理破坏共享工作区）
某只读 agent 为"恢复干净基线"执行 git checkout/stash，冲掉主会话未提交成果。
要素: a) 只读代理 git 写禁令（事前写入派单词，写明适用对象） b) 干净基线隔离机制（worktree/区间制） c) 派单前强制提交当期成果（机检化最佳：工作区脏即拒绝派单）

## C2 门禁假绿（退出码被管道吞）
门禁写成 `cmd | tail; echo $?`，取的是尾命令退出码——测试 exit=1 但门禁报通过。
要素: a) 取码方式声明/禁管道尾码（经封装记录器执行） b) 负向测试（故意红一条确认真报红，含记录链自身自检） c) 逐次退出码留痕可复查

## C3 夹具造假（手造形状掩盖退化）
测试夹具字段形状与被测引擎真实输出不符，渲染退化被"测绿"。
要素: a) 夹具必须是实跑 dump 的真实输出 b) 测试需真实业务断言非 mock 自证 c) 审查/机检能识别假夹具与"从未红过的回归测试"（AST 可查：mock-only 断言/大 sleep/顶层字面量形状；嵌套形状差靠语义审查）

## C4 全灭恢复（仓库非 git + 目录误删）
仓库没有 git，目录一删全灭，只剩旧备份。
要素: a) 灾难恢复第一动作=读状态文件不重做 b) 开工前提核验（git 化+备份目标可用，缺一不开工） c) 重建操作规程（基线+变更日志重放的明确步骤）；另查：状态文件自身是否有仓外副本

## C5 静默降级（fallback 链伪装验证）
指定 provider A 的验证请求返回 OK，实际是网关静默降级到 B 模型回答——能力与成本结论全错。
要素: a) 直连端点验证不经 fallback 链 b) 回读响应体实际模型 ID 核对 pin 值 c) 验证与使用同参数；另查：执行器自报"实际模型"字段是否有独立复核手段（自报可造假）

## C6 值抄写假故障（观测层打码）
工具/界面把敏感形态值显示成省略号/打码，执行者目测手抄常量导致假故障（且省略号可能是 U+2026 真实内容）。
要素: a) 禁手抄显示值 b) 常量从代码模块 import/直调/程序化 grep c) 异常值先怀疑观测层再怀疑被测层

## C7 历史折叠（agent 改写 git 历史）
修复 agent 执行 reset --soft 把多个提交折成一个，发布 tag 孤儿化。
要素: a) "改写已推送历史"在禁止/不可逆清单**明文枚举**（上位词兜底不算）且适用对象=所有被派 agent b) 执行前独立影响面检查（三问型） c) 机检：reflog 正则 + 孤儿 tag 可达性检测（merge-base --is-ancestor 逐 tag）；诚实核对：checkout -- file 不写 reflog，需工作区干净检查兜底

## C8 主张稀释（功能全绿结构已坏）
交付物功能清单全绿，但"X 模块解耦可单独订阅"类设计主张已被实现稀释。
要素: a) 价值门逐项对照约束清单且每约束绑证据 b) 开工前约束落到具体功能点（不落成可机检点禁 PASS） c) 结构性主张只认边界机检（AST 查跨模块 import 方向），不许主张方自选弱证据填满

## C9 游标错乱（压缩后重做+漏做双向）
上下文压缩后恢复，把已完成阶段重做、另一阶段漏做。
要素: a) checkpoint 状态文件机制（机器态/人读态/冻结护照分工） b) 冲突裁则明文（机器态唯一权威，禁反向迁就） c) 一致性机检脚本同时防两方向：游标不在已 PASS 阶段（防重做）+ 计划序列中游标前阶段必有 PASS 记录（防漏做）

## C10 墙钟卡死（时间轴无人值守）
单步卡死 2 小时无人发现，token 预算远未触顶。
要素: a) 墙钟时限熔断 b) 步骤级超时+心跳（心跳判卡必须含 fs mtime 双证据——ts 字段可被未来值/错时钟绕过） c) 触顶即停并上报；另查：看门狗是否独立于可能自身卡死的执行体（cron 外挂）

# 出题与评分要点

- 每题都是"协议里本应有一个位置"的坑：好协议答得出事前防线，差协议只能事后补救或彻底空白。"未覆盖"=0 分诚实标注不加罚，编造条款倒扣。
- 机械化是独立加分维度：同一流程有脚本/命令支撑 > 纯文字叮嘱；**注释/表格声称已实现但源码没有 = 不给分**（Runner 必须实读脚本源码点名不符）。
- 判据先于文档写死；出题上下文不得含被测文档内容或上一轮评测答案；每轮换新 Runner 防锚定。
